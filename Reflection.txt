3. One static member in my code is reportsCreated, which is declared on line 8 of DayReport,
private static int reportsCreated = 0;
I made this variable static because it counts the total number of DayReport objects created across the entire program. 
All DayReport objects share the same counter. If I changed it to a non-static variable, each object would have its own 
counter, so it would not correctly track the total number of reports created. One instance member is sales, declared on line 3,
private double sales; 
I made sales an instance variable because each day needs its own sales total. 
If I made it static, every DayReport object would share the same sales value, and the sales from different days 
would get mixed together.

5. My program uses checks to prevent errors when arrays are empty, full, or contain null elements.
For an empty sales array, the averageSales method checks whether the array length is zero before 
calculating the average (lines 738–740 of Cafe.java)
This prevents division by zero. The bestDaySales method also checks whether the array is empty before accessing 
sales[0] (lines 746–748). This prevents an ArrayIndexOutOfBoundsException.
For a full customer array, the addCustomer method checks whether there is space before inserting a 
customer (lines 64–70 of DayReport.java)
If the array is full, the method returns false instead of trying to insert an element outside the array's bounds.
For null customer values, addCustomer checks whether the customer is null (lines 60–62 of DayReport.java)
This prevents the method from storing a null customer. In addition, Cafe checks that a report is not null before printing it 
(lines 702–705). These checks help prevent a NullPointerException. The checks protect the situations they cover, although 
any future code that reads an array element directly should also check for null when necessary.
